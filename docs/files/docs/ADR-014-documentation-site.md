# ADR-014: the documentation is a public site built from the README

**Status:** accepted (2026-10-27) · **Decided by:** Lucas · Builds on [ADR-013](./ADR-013-delivery.md)

## Context
Lucas: "i want a github page with documentation from this section in readme: ## Documentation".
This repo is private and the organization is on GitHub's free plan, which does not serve Pages from a
private repo. The public `bluecollardev/downloads` repo already serves the download page (ADR-013).

## Decision
1. **The site is `https://bluecollardev.github.io/downloads/docs/`**, generated from this repo by
   `scripts/docs-site.mjs` and published by `./start.sh release docs` (it commits to the `docs/` folder of the downloads repo).
2. **The README's `## Documentation` section is the source of the navigation**: its sections and tables, in order.
   Adding a doc to the README table adds it to the site; no second list.
3. **The files are the Markdown files themselves**, rendered in the browser by a small viewer
   (`downloads/docs-viewer/index.html`, `marked` pinned from jsDelivr). No build tool, no dependency in the repo.
   Links between published docs stay in the viewer; links to anything not published show as plain text.
   Screenshots a doc references are copied beside it.
4. **The repo being public makes the site public, so what is published is chosen, not everything.** Left out, by
   the `EXCLUDE` list in the script: the client job (CANALV2, delivery packages, mount points, prompts, the import of
   shot packs), Binc's ShotPipe and governance material (`shared/`, the node packs doc), ADR-004 and ADR-008 (they
   describe the client job), planning and test records, `CLAUDE.md`, and the queue and projects inventories. The script
   also refuses to publish a document that matches a key pattern (`rpa_…`, `ghp_…`, `sk-ant-…`, a private key).
5. **The setup walkthrough is generated by a test.** `docs/SETUP-WALKTHROUGH.md` uses screenshots taken by
   `e2e-electron/walkthrough.spec.js` (`WALKTHROUGH=1`), which drives the real app as a new user would, so the guide breaks
   in the gate when the screens change.

## Consequences
- One command republishes the docs; the site never needs a release.
- A new doc about the client job must be added to `EXCLUDE` before it appears in the README table, or it goes public.
- The viewer needs a network connection to jsDelivr for the Markdown renderer.
- The walkthrough test starts the app with its own config folder; the app honours `POD_MANAGER_CONFIG_DIR` at start, so a test never reads the user's saved keys.
